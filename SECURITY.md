# Security Policy

## Supported versions

Security fixes are currently intended for the latest version on the `main` branch. SafeSignal is an educational heuristic tool, not an antivirus or a guarantee that a message or link is safe.

## Reporting a vulnerability

Please do **not** publish exploitable details, personal data, suspicious messages containing real credentials, or proof-of-concept attacks in a public issue.

Use GitHub's **Report a vulnerability** / private vulnerability reporting feature for this repository if it is available. If private reporting is unavailable, contact the repository maintainer privately through their GitHub profile and ask for a secure reporting channel before sending technical details.

Please include, when safe to do so:
- A short description and potential impact.
- The affected file, version, commit, or workflow.
- Minimal steps to reproduce, with synthetic data.
- Any suggested mitigation.

Do not include real passwords, authentication codes, payment information, private messages, or other people's personal data. Please allow time for the issue to be assessed and fixed before public disclosure.

## Scope and privacy

Reports about unsafe handling of local data, unintended network requests, dependency vulnerabilities, secrets accidentally committed to the repository, and exploitable application behavior are in scope. Avoid testing against systems or accounts you do not own or have permission to assess.

SafeSignal is designed to analyze text locally. Any future online reputation or external-service integration must remain explicitly opt-in and clearly disclose what data is transmitted.
